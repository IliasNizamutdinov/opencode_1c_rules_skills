# claude-md-bootstrap

Создает или дополняет проектный `AGENTS.md` — файл, который OpenCode загружает в каждую сессию.
В нем железные правила, протокол работы и указатели на документацию. Имя скилла сохранено из
исходного набора. Результат для OpenCode — `AGENTS.md`, не `CLAUDE.md`.

`CLAUDE.md` собирай только если пользователь явно работает в Claude Code. OpenCode 2 читает только
`AGENTS.md`. OpenCode 1 может взять `CLAUDE.md`, если `AGENTS.md` нет, но для этого набора основным
файлом остается `AGENTS.md`.

**Методика** — Variant E из `project-bootstrap`
(https://github.com/dimkurilo/opencode-skills/tree/main/skills/project-bootstrap): правила в начале
и в конце, классификация проекта, режим расширения, проверка противоречий, постепенное раскрытие,
не больше двух вопросов. Память Claude Code (`~/.claude/projects/.../memory/`) в OpenCode не
используется. Решения и грабли пиши в файлы репозитория, на которые указывает `AGENTS.md`.

## Когда этот скил, а когда встроенный /init

- **`/init`** — короткая сводка кодовой базы в `AGENTS.md`. Бери его, если нужен только обзор.
- **Этот скилл** — правила проекта в форме «если …, то …», протокол и указатели. Бери его, когда
  контекст должен переживать сессии.
- Можно совместить: черновик `/init`, затем этот скилл. Существующий `AGENTS.md` не перезаписывай.

## Workflow

### Фаза 0: Классификация + режим

1. **Тип проекта** (определи по файлам, НЕ спрашивай):

 | Тип | Сигналы |
 |-----|---------|
 | `code` | исходники (py/ts/js/go/...), тесты, CI |
 | `ops` | Docker, SSH, .env, nginx, продакшен-риски |
 | `agent` | скиллы, промпты, агенты, модели |
 | `content` | статьи, briefs, Excel, документы |

 Приоритет гибридов: ops > code > agent > content.

2. **Режим**: если в корне есть `AGENTS.md` — **режим расширения** (дополнять, не перезаписывать,
 сохранить правки пользователя, добавить недостающие секции). Маркерный блок набора 1С
 (`<!-- 1c-opencode-rules:start -->`) не переписывай: его обновляет установщик.

3. **Загрузи контекст** без вопросов:
 - `README*`, `docs/**`, корневые конфиги, `opencode.json`.
 - `git log --oneline -30` и исправления — источник граблей.
 - Глобальный `~/.config/opencode/AGENTS.md` и правила `~/.config/opencode/1c-rules/`, если они есть.
   Не дублируй их в проекте, дай ссылку.

### Фаза 1: Сбор (НЕ больше 2 вопросов)

Собери из контекста, спроси только то, что не выводится:
- **Overview** - 1 строка + 1 абзац (из README/кода).
- **Грабли (gotchas)** - из памяти, git-истории, троблшутинга в docs. Если неочевидно - ОДИН вопрос:
 "Какие грабли/правила в проекте обязательно знать, чтобы не наступить?".
- **Протокол** - команды запуска/тестов (из README/scripts/CI); правило "при изменении X обнови Y".
- Чего не знаешь - НЕ выдумывай, ставь `<!-- TODO: уточнить -->`.

### Фаза 2: Генерация AGENTS.md

Собери файл по шаблону ниже. Принципы:
- **Железные правила - дважды**: в преамбуле (primacy) и в конце (recency). Кратко, IF-THEN.
- **Постепенное раскрытие**: `AGENTS.md` — индекс. Не копируй сюда содержимое docs/, давай указатели.
- **Грабли конкретны**: симптом -> причина -> фикс/правило.
- В режиме расширения - вставляй только недостающее, существующее не трогай.

### Фаза 3: Contradiction check (обязательно)

Сверь `AGENTS.md` с глобальным `~/.config/opencode/AGENTS.md` и с правилами набора:
- нет правила, противоречащего глобальному;
- нет дублирования того, что уже лежит в правилах 1С (ссылайся на файл, не копируй);
- одно значение параметра во всех местах;
- без буквы «ё», без длинного и короткого тире (`-` вместо них), если этого требует `text-formatting.md`.
 Проверка: `grep -nP '[\x{451}\x{401}\x{2014}\x{2013}]' AGENTS.md`.
Конфликты исправь. Новые грабли запиши в файл проекта, на который ссылается `AGENTS.md`, а не в
память клиента.

### Фаза 4: Сводка

Что создано или дополнено, какие правила вынесены, что осталось как `TODO`.
`AGENTS.md` обновляй по ходу работы. Если файл стал длиннее 200 строк, вынеси детали в docs/.

## Шаблон AGENTS.md

```markdown
# ${PROJECT} - ${ONE_LINER}

> Проектный контекст для OpenCode. Это индекс: детали лежат в docs/.
> Не дублировать сюда содержимое docs/.

## Железные правила (всегда)
- IF ${условие или действие} THEN ${правило} # грабля/риск 1
- IF ${...} THEN ${...} # грабля/риск 2
- ${еще критичные инварианты проекта}

## Протокол работы
- Запуск: `${команда запуска}`
- Тесты: `${команда тестов}`
- Док как часть работы: изменил ${модуль} -> обнови ${docs/...}; добавил скрипт -> строку в README;
 новое решение или грабля -> файл, указанный ниже. Не копи документацию в долг.
- ${command-first / прочие конвенции}

## Архитектура (кратко)
${2-3 фразы про устройство}. Подробно - ${docs/архитектура}.

| Модуль | Файл | Ответственность |
|--------|------|----------------|
| ${...} | ${path} | ${за что отвечает} |

## Где что искать (progressive disclosure)
- docs/ - ${что в каком документе}
- Решения и грабли - ${docs/decisions.md или другой файл репозитория}
- Траблшутинг/грабли - ${docs/operations или ниже}

## Известные грабли (топ)
- ${симптом} -> ${причина} -> ${фикс/правило}

---
КРИТИЧНЫЕ ПРАВИЛА (повтор для recency):
- ${те же железные правила, одной строкой каждое}
```

## Что НЕ делать

- Не перезаписывать существующий `AGENTS.md`. Режим расширения.
- Не задавать больше двух вопросов. Остальное выводи из проекта.
- Не дублировать глобальный `~/.config/opencode/AGENTS.md` и правила набора 1С. Ссылайся.
- Не копировать docs/ в `AGENTS.md`. Только указатели.
- Не выдумывать факты. Если не знаешь — `<!-- TODO: уточнить -->`.
- Не раздувать файл: это индекс, не справочник.
- Не ставить служебные якоря, которые OpenCode не разбирает. Правила работают, потому что файл загружается целиком, а важные пункты повторены в начале и в конце.
