# File Edit Efficiency

Стратегия минимизации токенов при чтении и редактировании файлов.

Применяется: при любых операциях чтения/редактирования файлов.

---

## Выбор инструмента по задаче

В OpenCode те же роли выполняют инструменты чтения, поиска и точечной правки (read, grep, glob, edit) и shell. Имена в среде могут отличаться. Смысл правил не меняется: не загружать в контекст файл, из которого нужна одна строка, и не править десятки файлов по одному полному чтению.

### Массовые однотипные замены (N файлов, одинаковый паттерн)

**Поиск, затем одна замена, затем проверка:**
1. Поиском убедись, что шаблон один и тот же.
2. Замени его одним вызовом по всем найденным файлам.
3. Поиском проверь результат.

Не читай и не правь каждый файл отдельно. На N файлах это 2N вызовов и весь текст в контексте.

Массовую замену через `sed -i` делай только если шаблон буквальный и уникальный. Перед этим покажи, какие файлы затронуты. На Windows учитывай кириллицу в путях (`1c-cyrillic-windows.md`).

### Точечные правки (1-2 файла, нужна точность)

**Сначала чтение, потом точечная правка:**
- Правка по уникальному фрагменту безопаснее массовой замены.
- Файл читай один раз, дальше правь его несколько раз.
- Для большого файла читай диапазон строк, а не файл целиком.

### BSL-код в EDT-проектах (при наличии MCP)

**MCP read_method_source → write_module_source**:
- Читает/пишет конкретный метод, а не весь модуль (экономия на файлах 3000+ строк)
- write_module_source проверяет синтаксис автоматически
- Режимы: searchReplace, replace, append

### Поиск информации

| Задача | Как | Чего не делать |
|--------|-----|----------------|
| Найти файл по имени | поиск файлов по маске | обход дерева shell-ом и отдельный субагент |
| Найти строку | поиск по содержимому | читать файлы подряд |
| Прочитать фрагмент | чтение диапазона строк | читать весь файл |
| Структура большого модуля | MCP `get_module_structure`, если EDT подключена | читать модуль целиком |
| Широкий обход кодовой базы | субагент OpenCode, если он настроен | длинная серия ручных поисков |

### Ссылка на файл в ответе

OpenCode не дает курсорских `@`-ссылок на диапазон строк. В ответе указывай путь от корня проекта в обратных кавычках и номера строк текстом: `` `src/Catalogs/Контрагенты/Ext/ObjectModule.bsl`, строки 45-60 ``.

Путь с кириллицей не кодируй в markdown-ссылку: percent-encoding ломает его. Не читай файл целиком только ради того, чтобы показать путь.

## Кэширование больших карт в файл проекта

Если одни и те же крупные срезы нужны многократно за сессию (карта проекта, список модулей, каталог FQN, структура большого модуля) - сохранить результат ОДИН раз во временный markdown в проекте и работать с ним, не перезапрашивая MCP.

- Подходит для: `get_module_structure` больших модулей, `list_modules`, `get_metadata_objects` по конфигурации, `find_references` по якорным объектам рефакторинга.
- НЕ подходит для: `get_project_errors` (быстро устаревает после правок), результаты отладки, `get_form_screenshot`/`get_form_structure` (зависят от состояния редактора).
- Класть под gitignored-путь (например `.cache/edt-mcp/<имя>.md`). Не коммитить такие снимки.

## Антипаттерны

- **Чтение файла через shell и сразу правка**: правь по фрагменту, который сам прочитал инструментом чтения. Вывод `cat` легко обрезается и расходится с файлом.
- **Весь файл ради одной строки**: поиск или чтение диапазона.
- **Субагент ради одного поиска**: поиск по маске быстрее.
- **Последовательное чтение N файлов ради одной и той же замены**: одна массовая замена после проверки шаблона.
- **Перезапись всего файла ради одной строки**: точечная правка. Полная перезапись уместна, когда меняется структура файла.
