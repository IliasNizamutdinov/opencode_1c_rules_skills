# Уровни моделей в OpenCode

Применяется, когда нужно решить, хватает ли текущей модели или пользователю стоит переключить модель в OpenCode. Правило не привязано к Claude, GPT или Qwen: сравнивается способность модели, а не торговое имя.

Исходное правило набора Cursor назначало конкретные семейства Anthropic и внешние подписки. Здесь сохранены критерии выбора. Имена моделей заменены уровнями, потому что в OpenCode модель задает пользователь.

---

## Как в OpenCode выбирается модель

- Модель сессии задает пользователь: команда `/model` в TUI или поле `model` в `opencode.json`. Скилл и правило сами модель сессии не переключают.
- Субагент — это агент OpenCode (`.opencode/agents/` или ключ `agent` в конфигурации) со своим `model`. Если субагент не описан, изолированную работу не имитируй сменой модели посреди сессии.
- Кросс-ревью другим продуктом (отдельный CLI, другая подписка) допустимо только если этот инструмент уже установлен у пользователя. Не вызывай его по памяти и не подставляй ключи.

Три уровня:

| Уровень | Какая работа | Чего не отдавать |
|---|---|---|
| сильный | архитектура, безопасность, порча данных, многошаговая генерация метаданных и BSL, разбор типовой | механические списки файлов |
| рабочий | разведка BSL и метаданных, обычная реализация, ревью одного модуля | аудит RLS и прав, если есть сильная модель |
| быстрый | список файлов, поиск по тексту и логам, сводка документа по жесткому шаблону, правка опечатки | любой разбор кода 1С и метаданных |

Соответствие уровням в исходном правиле Cursor (это примеры, не требование ставить именно эти модели): сильный — Opus, рабочий — Sonnet, быстрый — Haiku. Модель «еще сильнее текущей» включается только по явной просьбе пользователя.

---

## Какой уровень нужен задаче

| Задача | Уровень |
|---|---|
| Проектирование, ломающие изменения, миграция | сильный |
| Аудит RLS, прав, чувствительных данных | сильный |
| Порча данных, гонки, регрессия проведения | сильный |
| Формы, запросы, объекты метаданных, расширение | сильный, если меняется несколько объектов; иначе рабочий |
| Навигация по выгрузке, «как работает этот модуль» | рабочий или сильный |
| Одна точечная правка с очевидным местом | рабочий |
| Список файлов, grep по журналу, сводка по шаблону | быстрый |

Длинный автономный прогон (сборка, загрузка, проверка, повтор) и первая реализация обмена по четкому ТЗ выигрывают от сильной модели. Единичная правка и вопрос по справке — нет.

---

## Субагенты

Субагент наследует модель родителя, пока в его определении не задан свой `model`. Уровень выбирай по типу работы, а не по ощущению «сложности».

| Тип работы | Уровень | Примеры |
|---|---|---|
| Механика вне BSL и метаданных | быстрый | список файлов, поиск по логу, сводка документа по формату |
| Разведка 1С | рабочий или сильный | структура модуля, ссылки, «как проводится документ» |
| Изолированная реализация и аудит | сильный | правка нескольких объектов, RLS, чувствительные данные |

- Разведку BSL и метаданных не отдавай быстрой модели. Неточная выжимка портит решение основной сессии.
- Проверку собственной правки отдельному субагенту не поручай: он видит тот же diff и подтверждает его. Проверка чужой работы — отдельный случай.
- Результаты тяжелых выборок MCP (широкий поиск, полный контекст объекта) по возможности оставляй в субагенте, в основную сессию возвращай выжимку. Если субагент не настроен, не дроби задачу искусственно: читай фрагмент, а не весь модуль.

---

## Поведение сильной модели

- Ревью проси полностью, с уровнем серьезности у каждой находки. Формулировка «только критичное» срезает дефекты, а не сортирует их.
- Уровень усилий соразмеряй с задачей. Цикл по нескольким модулям и диагностика проведения — высокий. Опечатка и справка — нет.
- Валидаторы набора, тесты и повторная проверка объекта не заменяются самопроверкой модели.

---

## Экономия контекста

- Читай фрагмент метода, а не весь модуль, если нужен один метод.
- Повторяющиеся карты (список объектов, структура большого модуля) сохрани один раз во временный файл проекта и не запрашивай заново. Не коммить такие снимки.
- Несколько независимых поисков запускай параллельно, если среда это позволяет.
- Разросшуюся сессию не растягивай: зафиксируй решения в файле плана (`agent-working-memory.md`) и продолжай с ним.

---

## Антипаттерны

| Антипаттерн | Как надо |
|---|---|
| Быстрая модель ведет основную сессию с разработкой 1С | рабочий или сильный уровень |
| Быстрая модель разбирает BSL или метаданные | рабочий или сильный уровень |
| Сильная модель считает файлы и грепает журнал | быстрый уровень |
| Скилл молча меняет модель сессии | предложить пользователю `/model` |
| Чтение всего модуля ради одного метода | читать метод |
| Проверка своего diff отдельным проходом той же модели | валидатор, тест или ревью другим контекстом |
